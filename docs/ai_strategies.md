# AI双模式投递策略设计

## 概述

为满足不同用户需求，系统支持两种投递策略：
1. **简单模式**：基于规则的自动投递，不依赖AI
2. **智能模式**：基于AI的个性化投递，需要AI服务

## 一、简单模式（无AI）

### 1.1 工作原理

基于预设规则进行投递决策：

```
用户配置
    ↓
关键词匹配 → 职位标题/描述包含关键词
    ↓
薪资过滤 → 符合期望薪资范围
    ↓
城市过滤 → 符合期望城市
    ↓
公司规模过滤 → 符合期望规模（可选）
    ↓
自动投递
```

### 1.2 核心功能

| 功能 | 实现方式 | 配置项 |
|------|----------|--------|
| 关键词匹配 | 字符串包含检查 | `keywords: ["Python", "后端", "开发"]` |
| 薪资过滤 | 范围比较 | `salary_range: [15, 30]` |
| 城市过滤 | 列表匹配 | `cities: ["北京", "上海"]` |
| 公司规模 | 范围匹配 | `company_size: [50, 500]` |
| 职位类型 | 精确匹配 | `job_types: ["全职", "远程"]` |

### 1.3 配置示例

```yaml
simple_mode:
  enabled: true
  keywords:
    - "Python"
    - "后端开发"
    - "FastAPI"
  salary_range:
    min: 15
    max: 30
  cities:
    - "北京"
    - "上海"
    - "深圳"
  exclude_keywords:
    - "外包"
    - "劳务派遣"
  max_applications_per_day: 50
```

### 1.4 优势

- ✅ 零成本：不需要AI API调用
- ✅ 速度快：规则判断毫秒级完成
- ✅ 可控性强：规则清晰透明
- ✅ 稳定性高：不依赖外部服务

### 1.5 局限

- ❌ 缺乏个性化：无法根据技能匹配
- ❌ 精确度低：可能投递不相关职位
- ❌ 无动态优化：不能根据反馈改进

## 二、智能模式（AI驱动）

### 2.1 工作原理

```
用户画像
    ↓
职位信息提取 → 获取职位详情
    ↓
AI分析匹配度 → 技能匹配、职业发展匹配
    ↓
生成个性化打招呼语 → 根据匹配点定制
    ↓
智能决策投递
```

### 2.2 核心功能

| 功能 | AI能力 | 输入 | 输出 |
|------|--------|------|------|
| 简历匹配 | 简历分析 | 用户简历 + 职位描述 | 匹配度分数(0-100) |
| 技能提取 | NER识别 | 简历文本 | 技能列表 |
| 打招呼生成 | 文本生成 | 匹配点 + 用户信息 | 个性化打招呼语 |
| 职位推荐 | 相似度计算 | 历史投递 + 新职位 | 推荐分数 |
| 投递优化 | 强化学习 | 投递结果反馈 | 策略调整建议 |

### 2.3 配置示例

```yaml
smart_mode:
  enabled: true
  ai_provider: "openai"  # openai/ollama/azure
  model: "gpt-4"

  user_profile:
    name: "张三"
    skills:
      - "Python"
      - "FastAPI"
      - "PostgreSQL"
      - "Docker"
    experience_years: 5
    target_positions:
      - "后端开发工程师"
      - "Python开发工程师"

  matching:
    min_score: 70          # 最低匹配分数
    skill_weight: 0.4      # 技能权重
    experience_weight: 0.3 # 经验权重
    salary_weight: 0.3     # 薪资权重

  greeting:
    style: "professional"  # professional/friendly/formal
    max_length: 200
    include_match_points: true

  learning:
    enabled: true
    feedback_days: 7
```

### 2.5 优势

- ✅ 高匹配度：精准匹配技能和需求
- ✅ 个性化：定制打招呼语
- ✅ 持续优化：根据反馈改进
- ✅ 智能推荐：发现隐藏机会

### 2.6 局限

- ❌ 有成本：AI API调用费用
- ❌ 依赖外部：需要AI服务可用
- ❌ 延迟较高：AI分析需要时间

## 三、混合模式（推荐）

### 3.1 混合策略

结合简单模式和智能模式的优势：

```
第一步：简单模式预筛选（快速）
    ↓ 职位通过预筛选？
    ↓ 是
第二步：AI深度分析（精准）
    ↓ 匹配度 >= 阈值？
    ↓ 是
第三步：生成个性化打招呼
    ↓
第四步：投递
```

### 3.2 配置示例

```yaml
hybrid_mode:
  enabled: true

  # 第一阶段：简单预筛选
  pre_filter:
    keywords: ["Python", "后端"]
    salary_range: [15, 30]
    cities: ["北京", "上海"]

  # 第二阶段：AI深度分析
  ai_analysis:
    enabled: true
    min_score: 70
    model: "gpt-4"

  # 第三阶段：智能打招呼
  smart_greeting:
    enabled: true
    style: "professional"
```

### 3.3 成本优化

| 策略 | AI调用次数 | 预估成本/天 |
|------|-----------|-------------|
| 纯简单模式 | 0 | ¥0 |
| 纯智能模式 | 100次 | ¥5-10 |
| 混合模式 | 30次 | ¥1.5-3 |

## 五、用户选择建议

| 用户类型 | 推荐模式 | 理由 |
|----------|----------|------|
| 预算有限 | 简单模式 | 零成本，速度快 |
| 追求精准 | 智能模式 | 高匹配度，个性化 |
| 平衡型 | 混合模式 | 兼顾成本和效果 |
| 技术岗 | 智能模式 | 技能匹配更重要 |
| 通用岗 | 简单模式 | 规则过滤足够 |
